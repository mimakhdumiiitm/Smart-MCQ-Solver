## 1. Abstract

This project addresses the Smart MCQ Solver Kaggle challenge, where the objective is to rank five answer options for multiple-choice questions and identify the correct answer. The pipeline progressively builds from lexical similarity baselines through transformer-based semantic models to retrieval-augmented generation and parameter-efficient fine-tuning. A final ensemble integrates all prediction sources. The best individual model achieved a MAP@3 of **0.9938** (RAG Semantic), while the final weighted ensemble achieved **MAP@3 = 0.9617** on validation and strong Kaggle leaderboard performance.

## 2. Introduction

### 2.1 Problem Statement

The competition requires a model to correctly identify the answer to science-domain multiple-choice questions, each containing a prompt and five candidate options (A–E). The primary evaluation metric is **MAP@3** (Mean Average Precision at 3), which rewards placing the correct answer within the top-3 predicted ranks.

### 2.2 Project Objectives

- Systematically compare lexical, semantic, retrieval-augmented, and fine-tuned transformer approaches
- Implement parameter-efficient fine-tuning (LoRA) to work within GPU memory constraints
- Build a multi-source ensemble that leverages complementary model strengths
- Track all experiments reproducibly via Weights & Biases (W&B)

### 2.3 Report Structure

The report covers dataset analysis → tokenization → three model families → comparative evaluation → ensemble → conclusion.

## 3. Dataset & Preprocessing

### 3.1 Dataset Description

| Split | Samples |
|---|---|
| Training | 2,000 |
| Validation | 400 |
| Test | 500 |

Each row contains a question prompt and five answer options. Labels indicate the correct option (A–E).

### 3.2 Exploratory Data Analysis

Key findings from EDA:

- **Answer distribution:** Mildly imbalanced — option B appears most frequently, followed by C, A, D, E. No severe skew was observed.
- **Text length:** Prompts average ~18 words; answer options average ~26–27 words with higher variance.
- **Prompt vocabulary:** Dominated by instructional language — *"correct," "option," "following," "based," "statement"* — indicating formulaic MCQ structure.
- **Option vocabulary:** Heavy scientific terminology — *"energy," "temperature," "particle," "mass," "density," "rotation"* — reflecting a physics/science domain.
- **TF-IDF similarity:** Distributions for correct and incorrect options overlapped heavily. Incorrect options sometimes scored marginally higher, making TF-IDF an unreliable ranking signal alone.
- **Word2Vec similarity:** Similar overlap issue; option E scored highest on average but differences across options were small.
- **Baseline ranking vs. similarity ranking:** Simple positional baselines outperformed both TF-IDF and Word2Vec (MAP@3), confirming that surface-level lexical similarity is insufficient.

### 3.3 Preprocessing

- Removed missing/empty text fields
- Whitespace normalization and consistent lowercasing for classical models
- For transformer models: raw text passed to model-specific tokenizers with padding and truncation to 512 tokens
- No heavy augmentation was applied; the dataset was sufficiently clean

## 4. Tokenization Strategy

### 4.1 Primary Tokenizer — DeBERTa-v3 (SentencePiece)

The best-performing fine-tuned model used **microsoft/deberta-v3-base**, which employs a **SentencePiece unigram tokenizer**. DeBERTa-v3 improves upon BERT by using disentangled attention (separating content and position embeddings) and an enhanced mask decoder, making it particularly strong for NLU tasks.

**Why effective:** SentencePiece handles scientific terminology robustly by subword decomposition, reducing out-of-vocabulary issues common in domain-specific MCQs.

### 4.2 Secondary Tokenizer — RoBERTa (BPE)

RoBERTa-base uses **Byte-Pair Encoding (BPE)** via HuggingFace's fast tokenizer. BPE is effective for general-purpose English text but slightly less robust for rare scientific terms compared to SentencePiece.

### 4.3 Implementation Details

All tokenization was implemented using the Hugging Face `transformers` library:

```
Input format per example:
[CLS] Question [SEP] Option_i [SEP]
→ Repeated for all 5 options
→ Shape: (batch_size, 5, 512)
```

Padding strategy: `max_length=512`, `truncation=True`, `padding="max_length"`.

### 4.4 Tokenizer Comparison

| Tokenizer | Model | Vocab Size | OOV Handling |
|---|---|---|---|
| SentencePiece | DeBERTa-v3 | 128,000 | Strong (subword) |
| BPE | RoBERTa | 50,265 | Moderate |
| TF-IDF Vectorizer | Baseline | Corpus vocab | Word-level only |

## 5. Modeling & Experimentation

### 5.1 Model 1 — Fine-Tuned Transformer (DeBERTa-v3 + LoRA)

**Architecture:**
DeBERTa-v3-base is a 12-layer transformer encoder with disentangled self-attention. It separates content and positional embeddings, enabling richer contextual understanding. It is adapted here as a **multiple-choice classifier** — five question-option pairs are scored simultaneously, and the highest logit selects the predicted answer.

**LoRA Configuration:**

```
Rank (r)       : 16
Alpha (α)      : 32
Target Modules : Attention projection layers
Trainable Params  : 2,679,553  (1.43% of total)
Total Params      : 187,102,466
```

LoRA inserts low-rank matrices (B·A, where rank ≪ full dimension) into frozen attention layers, enabling efficient adaptation without full fine-tuning.

**Fine-Tuning Details:**

| Hyperparameter | Value |
|---|---|
| Optimizer | AdamW |
| Epochs | 3 |
| Sequence Length | 512 |
| Backbone | Frozen (LoRA adapters only trained) |
| Platform | 2× Tesla T4 GPU |

**Training Curve — DeBERTa:**

| Epoch | Train Loss | Val Loss | Val MAP@3 | Val Accuracy |
|---|---|---|---|---|
| 1 | 12.16 | 2.92 | 0.7254 | 0.6075 |
| 2 | 10.65 | 2.55 | 0.7046 | 0.5675 |
| 3 | 9.28 | 2.43 | 0.6967 | 0.5575 |

### 5.2 Model 2 — Retrieval-Augmented Generation (RAG)

**Architecture Overview:**

```
┌─────────────────────────────────────────────┐
│              Query Question                  │
└───────────────────┬─────────────────────────┘
                    │
          ┌─────────▼──────────┐
          │  Sentence-BERT      │
          │ (all-mpnet-base-v2) │
          │  768-dim embedding  │
          └─────────┬──────────┘
                    │
          ┌─────────▼──────────┐
          │   FAISS CPU Index   │
          │  2000 train vectors │
          │  Top-K = 5 retrieval│
          └────┬───────────────┘
               │
    ┌──────────┴──────────┐
    │                     │
┌───▼────────┐    ┌───────▼──────────┐
│ Vote Score │    │ Semantic Context │
│ (weighted  │    │ Score (mean of   │
│  neighbor  │    │ retrieved answer │
│  votes)    │    │ embeddings vs.   │
│            │    │ options)         │
└───┬────────┘    └───────┬──────────┘
    │                     │
    └──────────┬──────────┘
               │
        Combined RAG Score
        → Rank Options A–E
```

**Salient Points:**
- No training required; leverages retrieved nearest neighbors from the training corpus
- Vote scoring: retrieved neighbors vote for the answer they correspond to, weighted by cosine similarity
- Semantic context scoring: mean embedding of retrieved correct answers compared to each current option
- FAISS enables sub-millisecond nearest-neighbor search at scale

**Results:**

| RAG Variant | MAP@3 |
|---|---|
| Vote Only | 1.0000 |
| Semantic Context Only | 0.9938 |
| Combined | 1.0000 |

> **Note:** Perfect MAP@3 on validation indicates strong retrieval quality — the training set contains highly similar questions to validation examples, making retrieval extremely effective.

### 5.3 Model 3 — Zero-Shot NLI Transformer

**Architecture:**
A pretrained Natural Language Inference (NLI) transformer is used in zero-shot mode. Each answer option is treated as a **hypothesis** and the question as the **premise**. The model's entailment probability scores are used directly to rank options — no fine-tuning required.

```
For each option i ∈ {A, B, C, D, E}:
  Input: [Question (premise)] → [Option_i (hypothesis)]
  Output: P(entailment) → used as ranking score
```

**Why suitable:** NLI models are trained to detect logical entailment, which aligns well with selecting the most plausible answer to a question.

**Results:**

| Metric | Value |
|---|---|
| MAP@3 | 0.5496 |
| Accuracy | 0.3825 |
| Macro F1 | 0.3803 |

## 7. Error Analysis & Insights

### 7.1 Where Models Fail

**TF-IDF / Word2Vec failures:**
These models rank options by surface lexical overlap with the prompt. Since all five options in science MCQs share similar terminology (e.g., "mass," "force," "energy"), the similarity scores cluster together, making discrimination impossible. Incorrect options frequently scored equal to or higher than the correct answer.

**Fine-tuned Transformer failures:**
The DeBERTa and RoBERTa models showed declining MAP@3 over training epochs despite decreasing training loss — a sign of **overfitting to the small 2,000-sample training set**. The models may have memorized answer patterns rather than learning genuine reasoning.

**RAG edge cases:**
RAG achieved a perfect MAP@3 of 1.0000 using vote scoring on the validation split. This near-perfect score likely reflects **data proximity** — the validation set contains questions similar enough to training examples that FAISS retrieval identifies near-duplicate items, effectively leaking the answer through retrieval. This may not generalize to held-out test data if the test distribution differs.

**Zero-Shot NLI failures:**
The NLI approach struggles when the question is phrased as a negation (e.g., *"Which of the following is NOT correct?"*), because the entailment model may assign high probability to technically true statements that are the wrong answer.

### 7.2 Key Insights

| Insight | Implication |
|---|---|
| Lexical similarity is insufficient for science MCQs | All future work should use contextual embeddings minimum |
| RAG quality depends on training-test proximity | Need to evaluate on fully held-out data to confirm generalization |
| LoRA with only 2K training samples may overfit | Larger datasets or stronger regularization required |
| Ensemble weights dominated by single model | Ensemble diversity needs improvement; more distinct model families needed |
| NLI zero-shot is a strong no-training baseline | Should be included in any MCQ ensemble as a free signal |

## 8. Conclusion & Future Work

### 8.1 Key Learnings

This project demonstrated that **retrieval-augmented approaches dramatically outperform both classical baselines and fine-tuned transformers** when the training corpus is representative of the evaluation data. Parameter-efficient fine-tuning (LoRA) successfully reduced GPU memory requirements, though a larger training set would be needed for meaningful generalization. The progressive pipeline — from EDA through baselines, zero-shot transformers, RAG, fine-tuning, and ensemble — provided clear evidence at each stage of where performance gains originate.

### 8.2 Challenges

- **GPU memory:** 5-way multiple-choice classification with 512-token sequences at batch size required careful gradient accumulation
- **Overfitting:** 2,000 training samples proved insufficient for robust transformer fine-tuning
- **RAG validity:** Near-perfect retrieval performance raised questions about data leakage that required careful interpretation

### 8.3 Future Work

1. **Larger training data:** Use the full competition dataset or augment via paraphrasing
2. **Generative models:** Fine-tune a seq2seq model (T5, FLAN-T5) to generate the answer directly rather than ranking
3. **Cross-encoder reranking:** Use a cross-encoder model to re-score top-K RAG candidates
4. **Calibrated ensembles:** Use Bayesian optimization or Optuna to optimize ensemble weights more systematically
5. **Test-time augmentation:** Paraphrase questions at inference time and aggregate predictions for robustness
