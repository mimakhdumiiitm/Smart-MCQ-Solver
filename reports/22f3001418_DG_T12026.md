## 1. Abstract / Executive Summary

This report presents the development of a Smart MCQ (Multiple-Choice Question) Solver built for a Kaggle competition. The task required ranking five answer options (A–E) for each science-domain question, with performance evaluated using Mean Average Precision at 3 (MAP@3). The project followed a progressive pipeline spanning five milestones: exploratory data analysis, transformer-based semantic ranking, retrieval-augmented generation (RAG), parameter-efficient transformer fine-tuning using LoRA, and ensemble learning.

Eight distinct models were developed and evaluated, ranging from classical TF-IDF and Word2Vec similarity models to fine-tuned transformer architectures (DeBERTa-v3, RoBERTa) and a FAISS-backed RAG system. The RAG Semantic model achieved the highest individual MAP@3 of **0.9938**, and the final weighted ensemble achieved a MAP@3 of **0.9617** on the validation set. The pipeline incorporated Weights & Biases (W&B) experiment tracking, artifact reuse, and automated model selection.

## 2. Introduction

### 2.1 Problem Statement

The Kaggle competition presented a multiple-choice question answering (MCQA) task in the scientific domain. Each question was paired with five candidate answer options (A through E), and the model was required to rank these options such that the correct answer appeared as high as possible. The primary evaluation metric was **MAP@3** — Mean Average Precision at rank 3 — which rewards models that place the correct answer within the top three predictions.

### 2.2 Project Objective

The primary objectives of this project were:

- Build a progressively improving answer-ranking pipeline
- Explore classical, neural, and retrieval-based approaches
- Fine-tune large pretrained transformer models using parameter-efficient techniques (LoRA)
- Combine all models into a robust ensemble system
- Maintain full reproducibility through artifact caching and experiment tracking

The report is organized as follows: Section 3 covers dataset analysis and preprocessing; Section 4 describes the tokenization strategy; Section 5 presents the three primary model architectures; Section 6 provides comparative performance analysis; Section 7 concludes with key learnings and future directions.

## 3. Dataset & Preprocessing

### 3.1 Dataset Description

The dataset consisted of multiple-choice science questions, each containing:

- A **prompt** (the question text)
- Five **answer options** labeled A through E
- A **correct answer** label

| Split | Samples |

### 3.2 Exploratory Data Analysis (EDA)

Several key insights were revealed during EDA:

**Answer Label Distribution**

The correct answer labels showed mild imbalance. Option B was the most frequent correct answer, followed by C, A, D, and E. The imbalance was not severe enough to require resampling.

**Text Length Analysis**

| Text Type | Average Word Count |
|---------------|-------------------|
| Prompts | ~18 words |
| Answer Options | ~26–27 words |

Answer options exhibited greater length variability than prompts, suggesting that answer text was more informationally dense.

**Vocabulary Analysis**

- **Prompt vocabulary** was dominated by instructional MCQ phrases: *correct, option, following, answer, based, statement, context*
- **Option vocabulary** was rich in domain-specific scientific terms: *energy, temperature, particle, mass, density, law, rotation, surface*

This contrast indicated that surface-level lexical matching between prompts and options would be unreliable, as the two text types occupy distinct vocabulary spaces.

**Semantic Similarity Analysis**

TF-IDF and Word2Vec cosine similarity distributions for correct and incorrect answers overlapped heavily. Incorrect options occasionally scored higher similarity than correct ones. This demonstrated that lexical similarity methods alone were insufficient for this task.

**Word2Vec PCA Visualization**

A PCA projection of Word2Vec embeddings confirmed that scientific domain terms clustered separately from instructional prompt words, validating the vocabulary gap identified above.

### 3.3 Data Preprocessing

The following preprocessing steps were applied:

- Removed null or empty text fields
- Stripped leading and trailing whitespace
- Normalized text casing where appropriate
- Concatenated question and option text for transformer input using the format:

```
[CLS] Question Text [SEP] Option Text [SEP]
```

- Applied padding and truncation to a maximum sequence length of **512 tokens**

### 3.4 Data Augmentation

No explicit data augmentation was applied. Instead, retrieval-augmented generation (RAG) was used in Milestone 3 to enrich each question with semantically similar training examples during inference, effectively providing implicit context augmentation.

## 4. Tokenization Strategy

### 4.1 Primary Tokenizer — DeBERTa-v3 (SentencePiece)

The primary tokenizer used was the **SentencePiece tokenizer** associated with `microsoft/deberta-v3-base`. DeBERTa-v3 uses a unigram SentencePiece vocabulary that handles subword tokenization effectively, particularly for scientific and domain-specific terms that may not appear as full words in standard vocabularies.

**Why DeBERTa-v3 tokenization is effective for this task:**

- Subword tokenization handles rare scientific terms without resorting to `[UNK]` tokens
- The model uses **disentangled attention** over content and position, making token position encoding more expressive
- SentencePiece vocabulary generalizes well across domains

### 4.2 Implementation Details

Tokenization was implemented using the Hugging Face `AutoTokenizer` API:

```python
tokenizer = AutoTokenizer.from_pretrained("microsoft/deberta-v3-base")

encoding = tokenizer(
    question,
    option,
    max_length=512,
    padding="max_length",
    truncation=True,
    return_tensors="pt"
)
```

For the multiple-choice format, input tensors were shaped as `(batch_size, 5, 512)` — one encoding per answer option per question.

### 4.3 Experimental Comparison

| Tokenizer | Model | Strategy | Notes |
|-----------|-------|----------|-------|
| SentencePiece | DeBERTa-v3-base | Subword unigram | **Best performing** |
| BPE | RoBERTa-base | Byte-Pair Encoding | Competitive, lower MAP@3 |
| WordPiece | Sentence-BERT | Subword | Used for retrieval embeddings |
| TF-IDF Vectorizer | Bag-of-words | N-gram | Weak baseline |

DeBERTa's tokenizer was selected as the primary tokenizer due to its superior downstream performance.

## 5. Modeling & Experimentation

### 5.1 Model 1 — Fine-Tuned Transformer (DeBERTa-v3 with LoRA)

#### Architecture

The primary model was `microsoft/deberta-v3-base`, a transformer encoder based on the **DeBERTa** (Decoding-enhanced BERT with Disentangled Attention) architecture introduced by He et al. (2021).

Key architectural features:

- **Disentangled attention mechanism**: Separate attention matrices for content and position
- **Enhanced mask decoder**: Absolute position embeddings reintroduced at the output layer
- **12 transformer encoder layers**, 768 hidden dimensions, 12 attention heads
- **Total parameters**: ~187 million

The model was adapted for **multiple-choice classification** by adding a linear classification head that scores all five options jointly.

#### LoRA Fine-Tuning

Instead of updating all parameters, **Low-Rank Adaptation (LoRA)** was applied, inserting trainable low-rank matrices into the attention layers while keeping the pretrained backbone frozen.

```
Architecture Diagram — LoRA Fine-Tuned DeBERTa

Input: [CLS] Question [SEP] Option_i [SEP]
         ↓
   DeBERTa Encoder (FROZEN)
   ┌─────────────────────────┐
   │  Self-Attention Layer   │
   │  + LoRA Adapter (r=16) │  ← Only this is trained
   │  Feed-Forward Layer     │
   │  (× 12 Layers)         │
   └─────────────────────────┘
         ↓
   [CLS] Representation
         ↓
   Linear Classification Head
         ↓
   Logit Score for Option_i

   (Repeated for all 5 options → argmax → prediction)
```

#### LoRA Configuration

|-----------|-------|
| LoRA Rank (r) | 16 |
| LoRA Alpha (α) | 32 |
| Trainable Parameters | 2,679,553 |
| Total Parameters | 187,102,466 |
| % Trainable | **1.43%** |

### 5.2 Model 2 — Retrieval-Augmented Generation (RAG) System

#### Architecture

The RAG system combines dense neural retrieval with similarity-based answer scoring, forming a custom deep learning pipeline.

```
RAG System Architecture

Training Corpus (2,000 Questions)
         ↓
   Sentence-BERT Encoder
   (all-mpnet-base-v2, 768-dim)
         ↓
   L2-Normalized Embeddings
         ↓
   FAISS Vector Index
   (CPU, Inner Product Search)
         ↓ ↑ Query Embedding
   Top-K=5 Nearest Neighbors

   ┌─────────────────────────────────┐
   │       Two Scoring Paths         │
   │                                 │
   │  Path 1: Retrieval Vote Score   │
   │  Weighted votes by similarity   │
   │  sim_score × correct_label →   │
   │  Accumulated per option         │
   │                                 │
   │  Path 2: Semantic Context Score │
   │  Retrieved correct answer texts │
   │  → Mean embedding (context vec) │
   │  → Cosine sim with each option  │
   └─────────────────────────────────┘
         ↓
   Combined Score = Vote + Semantic
         ↓
   Ranked Options (A–E)
```

#### Key Design Choices

- **Sentence-BERT** (`all-mpnet-base-v2`) was chosen for its strong semantic encoding in scientific domains
- **FAISS** enables scalable approximate nearest-neighbor search at retrieval time
- **Dual scoring** (vote + semantic) provides complementary evidence
- Retrieved contexts were formatted as `Q: [...] A: [...]` pairs for potential downstream generative use

#### System Configuration

| Component | Value |
|-----------|-------|
| Retrieval Model | sentence-transformers/all-mpnet-base-v2 |
| Embedding Dimension | 768 |
| FAISS Index Type | Flat Inner Product (CPU) |
| Top-K Retrieval | 5 |
| Training Corpus | 2,000 questions |

### 5.3 Model 3 — Zero-Shot NLI Transformer (RNN Baseline Comparison)

#### Architecture — Zero-Shot NLI Ranker

The Zero-Shot NLI model treats the MCQA task as a **textual entailment problem**. Each question-option pair is framed as a premise-hypothesis pair, and the model's entailment confidence score is used to rank the options.

```
Zero-Shot NLI Architecture

Question (Premise)
Answer Option_i (Hypothesis)
         ↓
   NLI Transformer Encoder
   ┌─────────────────────┐
   │  [CLS] Prem [SEP]  │
   │      Hyp [SEP]     │
   │  Encoder Layers    │
   └─────────────────────┘
         ↓
   3-class Classification Head
   [Entailment | Neutral | Contradiction]
         ↓
   P(Entailment) → Option Score

   (Repeated for all 5 options → ranked by score)
```

#### RNN-Based Bi-LSTM Baseline

As a secondary sequence model, a **Bidirectional LSTM** was implemented for comparison:

```
Bi-LSTM Architecture

Token Embeddings (GloVe / random init)
         ↓
   ┌─────────────────────────┐
   │  Bidirectional LSTM     │
   │  Hidden Size: 256       │
   │  Layers: 2              │
   │  Dropout: 0.3           │
   │  → Forward Hidden       │
   │  → Backward Hidden      │
   └─────────────────────────┘
         ↓
   Concatenated Final State

         ↓

         ↓

         ↓
```

### 6.1 Evaluation Metrics

The primary competition metric was **MAP@3** (Mean Average Precision at rank 3):

$$MAP@3 = \frac{1}{N} \sum_{i=1}^{N} \sum_{k=1}^{3} \frac{\text{Relevant}(k)}{k}$$

Additional metrics used for comprehensive evaluation:

- **Accuracy** — fraction of questions where the top-1 prediction is correct
- **Macro F1 Score** — unweighted average F1 across all answer classes
- **Precision & Recall** — per-class and macro-averaged

### 6.7 Error Analysis

Despite strong overall performance, several failure patterns were observed:

**Failure Pattern 1 — Lexical Overlap Confusion**

TF-IDF and Word2Vec models frequently ranked incorrect options higher when those options shared more surface-level vocabulary with the question. For example, a question about *"Newton's laws of motion"* would sometimes retrieve an option mentioning *"motion"* and *"force"* even when the correct answer used different phrasing.

**Failure Pattern 2 — Retrieval Boundary Cases**

The RAG system occasionally failed when no semantically close training examples existed. In such cases, retrieved neighbors were weakly related, causing vote scores to be distributed nearly uniformly across all options. These edge cases corresponded to the ~0.62% of validation examples where RAG Semantic was incorrect.

**Failure Pattern 3 — Fine-Tuned Transformer Overfitting**

The DeBERTa and RoBERTa models showed declining MAP@3 after Epoch 1, suggesting overfitting to the small 2,000-sample training set. The models appeared to memorize training patterns rather than generalizing, particularly for multi-step reasoning questions.

**Failure Pattern 4 — Transformer Embedding Underperformance**

The pure embedding similarity approach (MAP@3 = 0.2762) was the weakest transformer method. This occurred because cosine similarity between a question embedding and individual option embeddings cannot capture the reasoning relationship — it merely measures surface semantic proximity.

**Key Insight from Error Analysis:**

Models that incorporate structured reasoning (NLI entailment, retrieval voting) dramatically outperform models relying purely on embedding similarity. The task requires understanding *why* an answer is correct, not just *whether* the question and answer text are semantically similar.

## 7. Conclusion & Future Work

### 7.1 Key Learnings

- **Retrieval-Augmented Generation is extremely powerful** for knowledge-intensive MCQA tasks. When the training corpus contains similar examples, retrieval-based voting provides near-perfect answer ranking without any gradient-based training.
- **LoRA enables efficient transformer fine-tuning** with less than 1.5% of parameters trained, making it feasible to fine-tune large models within GPU memory constraints.
- **Simple similarity methods are insufficient** for scientific MCQA — the vocabulary gap between question prompts and answer options limits lexical approaches significantly.
- **Ensemble weighting must be performance-aware** — equal-weight ensembles performed far below the weighted approach, confirming that dominant models should receive proportionally larger contributions.
- **Experiment tracking with W&B** was essential for managing eight concurrent model experiments and automating model selection.

### 7.2 Challenges Faced

| Challenge | Resolution |
|-----------|-----------|
| GPU memory limits for full fine-tuning | Applied LoRA — only 1.43% of parameters trained |
| Repeated model inference in iterative runs | Implemented artifact caching with `.npy` files |
| GPU FAISS unavailable on Kaggle | Automatically fell back to CPU FAISS without loss of correctness |
| Overfitting on small training set (2,000 samples) | Early stopping; retained best epoch checkpoint |
| Score scale mismatch across models | Applied temperature scaling before weighted fusion |

### 7.3 Areas for Improvement

1. **Larger training data**: Augmenting with external science QA datasets (e.g., SciQ, ARC, MMLU) could substantially improve fine-tuned transformer performance and reduce overfitting.

2. **Advanced RAG with generative models**: Integrating a generative LLM (e.g., LLaMA, Mistral) to reason over retrieved contexts could push performance beyond the retrieval voting ceiling.

3. **Cross-encoder reranking**: Replacing the bi-encoder RAG retrieval with a cross-encoder that jointly encodes question-option pairs would improve discriminative ranking at the cost of inference speed.

4. **Hyperparameter optimization**: Systematic Bayesian hyperparameter search over LoRA rank, learning rate, and batch size could improve fine-tuned model performance.

5. **Model distillation**: Distilling the ensemble into a single compact model would improve inference efficiency while preserving performance.

6. **Chain-of-thought prompting**: For generative architectures, prompting with step-by-step reasoning before answering could improve accuracy on multi-step scientific reasoning questions.
